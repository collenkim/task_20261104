## 원인과 수정

`push-develop`은 develop의 첫 부모 경로만 검색했다. feature에서 만든 로그 커밋 `af793f02e046501445e35b8b697a9caa0deef9bc`가 두 번째 부모를 통해 포함돼 선택되지 않았지만, 마지막 검사는 모든 스냅샷을 요구해 `master_missing_develop_snapshots`가 발생했다. 모든 부모 경로를 위상 순서로 탐색하고 부모 하나·스냅샷 추가 전용 커밋만 선택하도록 수정했다. master 비로그 트리는 동기화 전후 같아야 한다.

느린 검사는 모든 과거 전체본을 매번 정밀 검사하고 동일 blob도 경로마다 검사했다. 병합 검사 뒤 pre-push에서 또 검사했고 모든 blob을 한꺼번에 읽었다. 통과한 blob·줄을 내용과 정책 해시로 기록하여 재사용하고, 크기를 제한한 배치로 읽도록 수정했다. 실패는 통과로 저장하지 않는다. 원본 앞부분 검사는 한 번 순회하면서 모든 기존 길이의 해시를 비교한다.

정책·검사 코드 변경, 내용 변경, DB 손상·잠금 시 재검사하며 원본·로그·Git index·ref는 검증 캐시가 변경하지 않는다. 진행 단계와 15초 간격 경과 시간을 표시한다. 캐시에는 원문·검출값이 없다.

## 실제 데이터 측정

측정 대상은 develop `4e8d32b1a94952d199a7a283a04f6bb29c682cf4`의 스냅샷 파일 47개 경로, 고유 Git blob 20개다. 고유 blob 총 크기는 246,860,619바이트다. 수정 후보로 실제 Git 객체를 읽었고 원본·스냅샷·브랜치는 바꾸지 않았다.

| 검사 | 시간 | 기존 통과 blob | 검사 결과 |
| --- | --- | --- | --- |
| 빈 캐시에서 시작 | 97.953초 | 0/20 | 비밀 검사 보류 0건 |
| 같은 트리·정책 재검사 | 0.062초 | 20/20 | 최초 결과와 동일 |

이 수치는 `scan_tree_secrets` 구간이다. 전체 sync·마스킹·원본 완전성·빌드·네트워크 전송 시간을 뜻하지 않는다. 최초 검사와 정책 변경 직후에는 전수 검사 비용이 남는다. 측정 JSON은 로컬 `.ai-logging/review-001/performance-benchmark.json`에 있다.

## 회귀 검사

기존 97개에 15개를 추가했다(캐시 14개, feature 로그 전달 1개). 최종 전체 실행은 112개 모두 통과했으며 202.832초가 걸렸다. 최초 후보 폴더에 빠졌던 Wrapper 속성 파일을 복사하고 전체 검사를 다시 실행한 결과다. 실제 모델 호출 없이 가짜 원본·임시 Git 저장소·로컬 bare 원격을 사용했다. 결과는 로컬 `.ai-logging/review-001/performance-tests-final.txt`에 보존했다.

- 새 줄만 검사, 중간 줄 수정·개행 없는 꼬리 연결·반복 검출의 줄 번호를 전수 검사와 비교.
- 치환·허용 목록과 검사 코드 변경 시 통과 기록 무효화.
- 캐시 파일·행 손상, DB 잠금 시 전수 검사. 캐시에 대화·검출값을 쓰지 않음.
- 여러 줄에 걸친 치환값 잔류 검출, 같은 blob 재사용·실패 경로 전체 보고, 읽지 못한 blob 차단.
- 이전 모든 길이의 원본 해시 비교, 수정·절단 검출.
- feature·develop 로그가 모두 master에 들어가되 기능 소스는 들어가지 않음, 같은 명령 재실행 시 중복 커밋 없음.
- 기존 원격 atomic push 거절 후 재개, 턴 보호, CRLF·마스킹·불변 스냅샷·예약 커밋 검증 유지.

## 한계와 후속

실제 GitHub push·master 병합은 모든 AI 턴이 끝난 뒤 사용자가 실행하는 절차에서 확인한다. 일반 개발 push가 원본 지연·보류를 경고로 처리하는 기존 정책은 바꾸지 않았다. Claude 부속 메타데이터의 `original_rewritten` 보류는 이 성능 수정으로 해소됐다고 보지 않는다. 최종 제출 완전성 판정은 별도다.
