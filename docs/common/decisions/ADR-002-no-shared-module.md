# ADR-002 서비스 공유 런타임 모듈을 두지 않음

| 항목 | 내용 |
| --- | --- |
| 분류 | 결정 기록 |
| 상태 | 확정 (2026-11-04) |
| 범위 | 멀티 모듈 구성, 서비스 간 코드 의존 |
| 관련 코드 | `settings.gradle.kts`, `build-logic/src/main/kotlin/task.spring-service.gradle.kts`(project 의존 검사) |

## 배경

- 요구사항: 서비스 간 직접 참조 불가(네트워크 API 호출만), 서비스별 독립 실행·배포.
- 두 서비스에 같은 코드(보안 설정, 오류 응답 처리, Swagger 설정)가 필요하다.

## 결정

- 서비스가 함께 쓰는 런타임 모듈(공통 DTO·엔티티·보안·유틸)을 만들지 않는다.
- 공유하는 것은 두 가지뿐이다.
  - 빌드 규칙: `build-logic`의 컨벤션 플러그인, `gradle/libs.versions.toml`
  - 공통 정책 문서: `docs/common/`
- 서비스 사이 `project(...)` 의존을 빌드에서 금지한다([POL-ARCH-002](../architecture.md#pol-arch-002-직접-참조-금지)).

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 공통 라이브러리 모듈(`common`) | 한 모듈을 바꾸면 두 서비스를 함께 재빌드·재배포해야 하고, 공통 DTO가 서비스 계약을 묶는다. 채택하지 않음 |
| 별도 저장소의 사내 라이브러리 | 이번 과제 범위에 비해 배포·버전 관리 부담이 큼. 채택하지 않음 |

## 결과

- 보안 설정·오류 처리기·Swagger 설정이 서비스마다 중복된다. 규칙은 공통 문서 하나로 관리하고, 두 서비스의 같은 테스트(`CommonPolicyTests`)로 동작을 맞춘다.
- 한 서비스의 코드를 바꿔도 다른 서비스는 재빌드할 필요가 없다. 공통 빌드 규칙을 바꿀 때만 두 서비스를 모두 빌드·테스트한다.
