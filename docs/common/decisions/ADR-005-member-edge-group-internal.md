현재 유효한 기준은 아래 최초 결정에 2026-11-05 GROUP-001 추가 결정과 2026-11-06 ADR-006을 적용한 것이다. 그룹 명세의 읽기 전용 제한은 해제되었고 멤버 경유 두 GET 실행은 local 프로필에서만 JWT(`group.read`)로 허용한다. 그룹의 내부 호출 키 검사는 유지한다. 사용자 인증 제외는 ADR-006으로 대체되었다.

## 최초 결정 (2026-11-04)

- 멤버는 사용자 진입점이고 그룹은 내부 IP:PORT의 서비스다. 호출 방향은 멤버 → 그룹이다.
- 사용자 인증·인가는 범위에서 제외한다. 기존 JWT 방식을 공유 시크릿 헤더 `X-Internal-Service-Key`로 대체한다.
- 그룹은 키가 맞는 요청만 처리한다(health·오류 처리 제외). 멤버가 내부 키를 자동 첨부한다.
- 멤버 Swagger에서 두 명세를 선택한다. 멤버 명세는 실행 가능하고 그룹 명세는 읽기 전용이다. 그룹 명세는 멤버 서버가 받아 전달한다.
- 명세 전달은 local 전용이 아니다. 사용자 요청대로 명세를 공개하지만 키와 그룹 직접 접근 경로는 공개하지 않는다.
- 그룹 Swagger UI는 제공하지 않는다. 별도 게이트웨이는 추가하지 않는다.
- 그룹이 중단돼도 멤버는 기동한다. 그룹 의존 명세 요청은 503으로 실패한다.

## 배경과 대안

사용자 인증 체계를 만들기보다 두 독립 서비스와 단순한 내부 호출 절차를 우선한다. JWT·OAuth 서버·mTLS는 이번 범위의 복잡도를 늘려 적용하지 않는다. 공유 키는 프로세스 신원 증명이 아니므로 외부 호스트 간 통신은 HTTPS와 네트워크 접근 제한을 함께 적용한다.

기존 ADR-003은 대체됨으로 남긴다. 업무 API를 외부에 중계하는 기능은 명세 공개와 별도이며 현재 범위가 아니다.

## GROUP-001 추가 결정 (2026-11-05)

사용자 요청으로 그룹 명세의 읽기 전용 제한을 해제한다. 그룹 두 GET은 멤버의 고정 /internal-api/group 중계로 실행한다. 내부 포트·호출자 인증·키 서버 보관은 유지한다. 상세 기준은 [구현 요청서](../../tasks/GROUP-001/request.md#8-swagger-그룹-실행--추가-확정-요구)를 따른다.
