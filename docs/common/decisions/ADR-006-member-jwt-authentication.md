## 배경

필수 요건 검토에서 멤버 API의 JWT 인증과 Swagger 자동 토큰을 사용자 확정 요구로 다시 정했다. ADR-005는 사용자 인증을 범위에서 제외했고, ADR-003의 고정 키·토큰 방식은 키를 저장소에 둘 수 없어 폐기되었다. 사용자는 "`secrets/`가 커밋되지 않으니 프로젝트 init 때 키를 생성해 처리하라"고 방향을 정했다.

## 결정

- 멤버의 업무 API(`/api/**`)와 그룹 중계(`/internal-api/group/**`)는 RS256 JWT Bearer를 요구한다. Spring Security OAuth2 Resource Server로 서명·`iss`·`aud`·`exp`·`nbf`·`sub`를 검증하고 경로별 scope(`member.read`, `group.read`)를 요구한다.
- 검증 공개키와 local 서명 키는 `generateLocalSecrets`(init)가 RSA 2048 키 쌍으로 만든다. 저장소에는 키도 토큰도 두지 않는다. 운영은 외부 발급 서버의 공개키를 같은 configtree 위치에 둔다.
- local 프로필에서만 Swagger 초기화 스크립트에 요청마다 새로 서명한 짧은 만료 토큰을 넣는다. 고정 토큰은 만들지 않는다.
- 그룹 중계와 그룹 명세 전달은 local 프로필에서만 켠다(`task.group-proxy.enabled`). 그 밖의 프로필에서는 사용자 진입점에서 그룹에 닿는 경로가 없다.
- 인증된 subject별 요청 제한(429)을 둔다. 그룹 내부 호출은 계속 공유 키 헤더로 인증하며 사용자 토큰을 전달하지 않는다.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 저장소에 고정 키·토큰 커밋(ADR-003) | 비밀값 커밋 금지와 충돌. 폐기 |
| HS256 공유 비밀 | 검증자도 발급할 수 있어 운영 IdP 전환 시 키를 공유해야 함. 비대칭 RS256 선택 |
| local 고정 토큰 파일 생성 | 만료·교체 관리가 필요하고 유출 시 계속 유효. 요청마다 짧은 만료 토큰 서명 선택 |
| 인증 서버(OAuth AS) 추가 | 과제 범위를 넘는 구성. 발급은 외부 IdP 책임으로 두고 자원 서버만 구현 |
| 인증 없이 유지(ADR-005) | 사용자 확정 요구와 충돌 |

## 결과

- 토큰 없음·검증 실패는 401 `UNAUTHORIZED`, scope 부족은 403 `FORBIDDEN`이다. 401에는 RFC 6750 헤더와 RFC 9728 메타데이터 위치가 붙는다.
- 키 쌍이 짝이 아니면 local 멤버 앱이 기동하지 않는다. 기본 프로필은 공개키만 필요하다.
- 테스트는 실행 중 만든 키 쌍과 토큰만 쓴다. 상세 규칙은 [POL-SEC-001·004·005·006·007](../security.md)을 따른다.
- 토큰 발급 서버·키 순환(JWKS)·분산 요청 제한은 운영 배포 때 정한다. 현재 구현 완료로 표시하지 않는다.
