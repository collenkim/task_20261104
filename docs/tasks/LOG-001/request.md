## 확인 가능한 요구와 최종 흐름

Codex와 Claude Code의 프로젝트 세션 전체를 자동 수집한다. 최초 요청부터 프롬프트·응답·명령과 출력·파일 수정·서브에이전트 기록을 보존한다. 다른 프로젝트는 제외하며 중단·실패·재개 세션도 선택적으로 빼지 않는다. 원본은 수정하지 않고 제출 사본에서 비밀값·개인정보만 마스킹한다. 줄 순서와 원본성을 검증하고 도구별 전체본을 ai-logs/에 제출한다.

hook·스크립트·설정·README의 사용 도구와 수집 방식 설명을 저장소에 둔다. 등록·live·치환 목록·보류 등 운영 상태는 Git에서 제외한다. 추적 스냅샷은 수집기만 만들고, 소스·정책·브랜치 변경에도 기록을 보존한다.

작업 feature는 master에서 시작한다. develop은 통합 검증용이며 로그 전용 커밋만 master에 동기화한다. 검증한 feature를 master에 일반 병합하고 develop 소스 전체는 병합하지 않는다. AI 턴 중 공유 index·브랜치 변경을 피하고 승인된 커밋은 예약한다. master 병합·push와 턴 상태 수동 해소는 사용자 절차다.

## 이력과 현재 상태 구분

최초의 마지막 1회 제출안, live와 스냅샷의 분리, develop 로그 동기화, 일반 개발 중 보류 경고 허용 등은 대화와 구현 중 발전한 결정이다. 계획에는 당시 논의가 남아 있으므로 실행 명령은 현재 운영 문서를 따른다. commit 99e053d는 보류 세션이 일반 로그 게시를 모두 막지 않도록 바꾼 근거이며, 최종 제출 완전성 통과를 면제하는 근거는 아니다.

당시 검증의 실제 모델 호출 여부·실행 한계를 보존한다. REVIEW-001에서 관찰한 meta.json 재작성 보류와 Codex hook 실행 미확인은 [새 검토 기록](../../verification/REVIEW-001/findings.md)에 따로 적는다. 이 요청서는 로그 전체의 누락 없음이나 모든 과거 중간 커밋의 완전성을 증명하지 않는다.
