# 작업 기록 색인

| 항목 | 내용 |
| --- | --- |
| 분류 | 작업 색인 |
| 상태 | 현재 |
| 목적 | 작업 당시 요청·계획과 후속 변경을 구분한다 |

| 작업 | 요청 | 계획 | 기록 성격 |
| --- | --- | --- | --- |
| SETUP-001 | [사후 요청 정리](SETUP-001/request.md) | [구성 계획](SETUP-001/plan.md)·[구조 변경](SETUP-001/structure-change-plan.md) | 이력 |
| LOG-001 | [사후 요청 정리](LOG-001/request.md) | [로깅 계획](LOG-001/plan.md) | 이력. 현재 운영은 common/ai-logging.md |
| MEMBER-001 | [요청](MEMBER-001/request.md) | [계획](MEMBER-001/plan.md) | 이력. GROUP-001의 소속·시각·권한 변경으로 일부 대체 |
| GROUP-001 | [요청](GROUP-001/request.md) | [계획](GROUP-001/plan.md) | 이력. 현재 구현의 근거 |
| REVIEW-001 | [요청](REVIEW-001/request.md) | [문서 계획](REVIEW-001/plan.md)·[결정](REVIEW-001/decisions.md)·[인계](REVIEW-001/handoff.md) | 문서 정비·후속 계약 검토 |
| REVIEW-002 | [요청](REVIEW-002/request.md) | [코드 계획](REVIEW-002/plan.md) | 후속 계획, 구현 미착수 |

REVIEW-002는 REVIEW-001 반영 후 master에서 만든다. 작업 문서의 이름이나 존재만으로 브랜치 생성·구현·승인이 완료되었다고 판단하지 않는다. 현재 기준은 [공통·서비스 정의](../README.md), 실제 완료 증거는 [검증 기록](../verification/README.md)을 확인한다.
